# Agent Note: 多用户错误处理与校验精简

Status: implemented

## Problem

个人配置读取失败会被自动备份并重建为空配置，公共音源日志在宿主停止后返回假成功，重启 RPC 实际只读取列表。公共图标残留 32 个上限，歌单 RPC 和备份入口重复执行服务已有的递归校验。

后续审查发现草稿校验失败也执行全站回滚，安装失败遗留的暂存 token 会耗尽八项额度，普通账号 RPC 包装重复处理下层已经固定或脱敏的返回值。

## Decision

删除配置自动恢复及无用日志参数，沿用 Store 的正常读取和缺文件初始化，读取或解析错误直接上抛、原文件不动。Web 单用户入口共用该工厂；桌面恢复行为不变。

日志读写在宿主不可用时沿用已有错误分支；前端清理成功后才清空显示，失败复用现有通知。保留初始化所需的空资源列表。删除图标数量上限，保留路径和类型检查。

删除多用户的伪重启实现，由已有权限规则拒绝该 RPC，测试实际关闭并重建账号上下文。个人数据递归校验统一在 createMusicList 中执行，备份格式及结构检查保留。不增加服务层、配置项、错误分类或恢复框架。

发布按是否进入正式切换区分恢复范围：草稿校验失败只恢复原先运行且已成功关闭的管理员，正式切换失败才回滚全站。回滚中公共音源停止失败记入错误并继续尝试恢复，避免跳过失败审计；管理员恢复失败附加到原始校验错误。安装和更新尝试在 finally 消费暂存 token，保留八项上限；RPC 删除下层已处理的三个重复返回分支。

## Alternatives considered

统一回滚可以复用同一路径处理所有失败，但草稿无效不应中断其他账号。失败保留 token 便于重试同一个包，但底层可能已删除包目录，且正常界面会重新下载，残留 token 会耗尽额度；因此每次安装尝试结束就释放。权限检查及扩展信息脱敏仍保留。

仅对格式损坏保留自动备份恢复，能让坏配置账号继续启动，但需要额外区分错误并持续维护隐式重置行为；用户选择直接失败并保留原文件。宿主外独立读取历史日志有助于故障排查，但会新增第二条日志访问路径，本次仅删除假成功。多入口校验便于各自阅读，但同一请求重复深扫，保留所有写入经过的服务校验即可。

## Testing

本轮账号测试 22 项、公共音源测试 3 项通过，账号 TypeScript 检查及 Web 构建通过。新增模拟 Worker 用例覆盖安装和更新各连续失败九次后正常安装、旧 token 失效及八个未消费 token 的上限。发布用例覆盖无效草稿保留普通账号实例且不停止音源、管理员恢复及恢复失败、原先停止的管理员不自动启动、失败审计与快照清理、正式切换及回滚连续停止失败后仍尝试恢复。真实账号 RPC 验证默认返回值、资源字段过滤及已有权限/脱敏检查。以下为首轮精简的验证记录，本轮未重复桌面或浏览器验证。

Windows、Node.js 26.10.0 下，账号 21 项、播放器与 Store 7 项、公共音源 3 项、歌单 9 项共 40 项测试通过，Web 构建及账号 TypeScript 检查通过。构建保留现有 import.meta、Svelte 状态引用和大包警告。

配置测试验证正常读写及隔离、坏 JSON 和模拟 EACCES 不修改原文件或生成备份。公共音源测试验证正常日志操作、宿主停止时失败且日志文件不变、初始化仍可取空资源列表，以及 33 个带图标扩展全部加载。账号测试实际关闭并重建管理员上下文与草稿 Worker，验证配置保留、伪重启 RPC 拒绝、禁止的个人字段不能经备份导入。

浏览器在独立 work/account-cleanup-check-20261014 数据中验证：先显示真实扩展历史日志，再停止音源宿主并点击清空输出，页面提示 No public source is published 且原日志仍保留。截图保存为该目录的 logs-failure.png，预览进程和浏览器标签页均已关闭。

## Consequences

首轮精简业务代码净减少 14 行；本轮增加发布阶段判断并删除重复 RPC 返回处理，无新依赖、数据库迁移或恢复框架。安装失败后旧 token 失效，需重新下载后重试。损坏配置需要手动修复后才能启动账号；宿主不可用时通过部署日志文件排查。保留现有永久删除及其他未提交改动，不触碰真实用户数据。未运行完整桌面回归或真实外部音源测试。
