# Agent Note: 歌手作品按页播放

Status: implemented

## Problem

点击已显示歌曲仍串行获取歌手全部作品；扩展每页最多 30 首，首播等待随作品数增长。

## Decision

单曲复用当前页，顺序按钮从第一页开始，接近队尾三首时补下一页。全集随机继续取全量，失败不局部随机。补页状态随账号队列保存，使用现有 metadata，不新增表。队列标识和预期页码在数据库提交时核对，歌曲与页码同事务写入，防止多设备重复追加和旧请求污染新队列。失败保留现有数据，手动下一首重试，不增加自动恢复、通用分页框架或队列编辑功能。

## Related decisions

检索 singer、歌手、分页：[歌手播放](../../implemented/feature/2026-10-09-singer-playback.md)部分重叠，本篇取代播放前取全量的决定，保留其来源与快照规则；歌手元数据、主线隔离、歌单运行成本和在线导航笔记各自决定保持有效；发布流程与本改动无关。没有完全吸收或需归档的旧篇。

## Alternatives considered

全量获取后播放最容易保持完整队列顺序，但点击耗时与作品数成正比。并行拉取全部页能减少独立请求延迟，但共享音源宿主本就串行执行，且不需要在首播前取得全量。仅在页面内存保存分页最简单，但刷新和其他设备无法续播，不符合已确认需求。

## Testing

歌手 14 项、歌手扩展 13 项、播放器 7 项、账号 21 项、公共音源 3 项及数据库 8 项测试通过。覆盖当前页不请求、跨页、空末页、全集随机、失败手动重试、重开恢复、双连接并发提交与过期请求拒绝，以及 SQL 失败后数据库和内存均不变化。

Web、桌面源码构建和账号类型检查通过。`git diff --check` 与 `npm run verify-notes` 通过。前端全量检查仍为已有的 168 错误、17 警告，本次修改文件没有新增报错。浏览器使用隔离测试源，后续页延迟 2.5 秒，点击当前页约 243 毫秒显示播放中；验证刷新恢复、另一页面继续补页、双页面队列同步和独立的全集随机准备提示。测试音频为合成静音，不代表真实平台解析与出声验收。

## Consequences

首播不再等待全量作品。元数据直接查询现有小型 JSON 记录，去掉单独缓存，避免事务回滚留下已更新缓存；恢复时歌曲和分页状态在同一个数据库调用内读取。增加的是歌手专用队列状态与动作，没有通用框架。

外部音源的分页内容可能变化，按现有 ID 去重，不实现远端快照。音频地址解析耗时仍存在。
