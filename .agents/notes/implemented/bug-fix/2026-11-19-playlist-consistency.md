# Agent Note: 歌单同步、选择与队列确认

Status: implemented

## Problem

在线歌单曲目和同步元数据分两次提交，并发编辑可能被旧快照覆盖。手动请求复用被取消的后台任务时可能报告成功，尽管没有写入曲目。

## Decision

在线同步在账号 DB Worker 的 SQLite 事务内校验拉取前的歌单与最新状态，并更新曲目和同步字段。自动任务同时检查开关。曲目保留已有的同 ID 信息。事务成功后才刷新缓存和广播。首次收藏仍可在自动同步关闭时拉取。

手动请求等待实际提交，可共享同歌单正在进行的拉取。若后台结果过期，共用条目移到队尾并按最新歌单重试一次。手动结果再次过期、歌单已删或连接所属账号关闭时返回错误。源请求本身失败时直接返回该错误。

## Alternatives considered

在服务层保存前再读一次改动较少。两次写入之间仍可发生并发编辑或部分失败，因此在现有账号 DB Worker 一次提交。手动操作可以始终独立抓取以简化状态判断，代价是同一歌单的重复源请求，因此先共享有效结果，过期后单次重排。

## Testing

SQLite 回归覆盖改名、关闭自动同步、删除、元数据写入失败与数据库重开。同步队列回归覆盖双账号隔离、共享结果、一次重排和再次过期后的错误。账号 TypeScript 检查通过。

## Consequences

提交前快照变化会丢弃已抓取的数据。手动重排会再次访问音源，界面只在提交成功后提示同步完成。使用现有 RPC 和 SQLite 格式。
