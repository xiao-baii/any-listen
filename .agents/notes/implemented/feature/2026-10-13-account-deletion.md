# Agent Note: 已禁用账号的永久删除

Status: implemented

## Problem

账号只能禁用，个人数据和用户名一直保留。管理员需要永久移除不再使用的普通账号，同时不能影响其他账号或让部分删除的账号重新登录。

## Decision

管理员只能删除已禁用的普通账号。界面复用确认弹窗，DELETE /account-api/users/:id 复用权限和 Origin 校验。沿用维护锁排空启动，再在现有 state 表写 user.deleting:<UUID> 标记，断开连接并停止账号，清理个人数据和当前进程临时目录，最后事务删除账号、会话和标记并写审计。

删除标记禁止恢复和改密；文件清理失败保持标记，由管理员再次删除，不自动重试或回滚文件。停止失败保留失败的 Promise，不能在同一进程内跳过关闭继续删除。正常账号的现有“重试启动”清除已结束的停止失败，保留 DB Worker 故障恢复能力；禁用账号不能调用此接口。发布和音源重载只有拿到维护锁才执行回滚或释放锁。登录在异步密码验证后处理账号已删除的情况。

## Alternatives considered

只删账号记录最短且立即释放用户名，但留下个人目录，并可能在运行任务未结束时继续写入，因此先停止、清理目录再提交删除。无删除标记无需扩展列表状态，但文件部分删除后仍可恢复账号，会把残缺数据当成可用账号，因此保留一个持久标记。

回收站或后台清理任务方便撤销和自动完成，但用户要求永久删除及最小实现，因此不新增服务层、任务框架、自动恢复和历史临时目录扫描。

## Testing

Windows、Node.js 26.10.0 下，账号集成 21 项、账号入口 2 项、账号 TypeScript 检查和 Web 构建通过。新增测试覆盖权限、管理员保护、先禁用、数据清理、用户名复用、停止与清理失败、数据库事务失败、重启后标记保留、异步登录与改密、恢复与发布并发，以及其他账号不受影响。原有 DB Worker 故障恢复回归通过。

隔离的本地预览验证正常账号没有删除入口、禁用后出现按钮、确认文案、取消保留账号、删除后列表刷新及关联重置表单清除、同名账号重建。npm run verify-notes 和 git diff --check 通过。构建仍有原有 import.meta、Svelte 状态捕获和大 chunk 告警，未扩展修复；未做生产部署或 Linux 容器验收。

## Consequences

失败可能已删除部分文件，只能继续删除。维护期间新账号启动等待，已运行账号保持运行。系统审计、外部备份和旧进程临时目录不清理；停止失败须重启服务后继续。
