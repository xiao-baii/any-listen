# Agent Note: 歌手筛选播放与在线歌手资源

Status: implemented

## Problem

歌单搜索只定位歌曲，播放仍使用完整歌单。在线 singerSearch / singer 只有能力声明，缺少资源接口和页面。

## Decision

我的歌单按现有 singerFormat 规则选择单个歌手，选择只改变显示，播放才创建独立队列快照。快照清除旧队列、历史和预取结果，队列 listId 为 null，歌曲保留原 listId/source，避免初始化和歌单同步重新补全。在线歌单不变。

扩展新增 singerSearch 分页歌手查询和 singer 分页作品查询，贯通 SDK、校验、资源服务、IPC 和页面。作品播放先取全量，成功后才替换队列。不兼容猜测外部扩展返回值，不添加回退搜索。

Web 普通账号的允许列表包含这两个只读资源接口，不开放扩展管理权限。歌手来源在播放列表数据库中映射为 5；歌曲 listId 保存来源和歌手 ID 的 URL 查询参数，使播放栏能返回作品页。现有数字映射保持不变，无表结构迁移。

独立队列随机历史按 itemId 是否仍在当前队列中判断；原来的 listId 判断不适用于无关联快照。歌单同步读取返回后检查目标关联仍有效，防止在途同步覆盖新快照。

## Alternatives considered

复用普通歌单播放入口最省代码，但它重新读取完整歌单并关联同步，会破坏筛选范围，因此使用独立快照入口，复用现有队列工具和切歌算法。

按歌手名复用歌曲搜索不需要新扩展接口，但不能可靠提供歌手身份和作品全集，因此采用真实歌手资源能力。

## Testing

`npm run test:singer` 覆盖歌手规则、普通账号权限、SDK 与测试扩展、作品分页失败、快照替换、旧预取清除、循环、随机历史与恢复播放。现有 player.test.ts、database.test.ts、sharedSources.test.ts 验证播放器回归、数据库重开与实际扩展进程调用。

浏览器使用隔离的本地测试账号和测试扩展，检查 320/375/430px 手机及 1200px 桌面，验证选择框不溢出、44px 点击区域、长名称省略、歌手搜索、作品翻页和跨页队列。

前端、SDK、Web 服务及 IPC 构建通过。全量 svelte-check 报告 171 个错误和 17 个警告，错误均不在本次修改文件，涉及已有依赖声明、组件参数和音频处理 JS；未在此次功能中扩大修复。测试源不提供真实音频，出声和外部音乐源适配不在已验证范围。

## Consequences

复用现有播放模式，无需新数据库字段或播放器算法。真实歌手搜索依赖仓库外扩展适配；快照不会随原歌单自动更新，显式添加稍后播放仍按现有行为生效。原稍后播放队列在开始筛选播放时被替换。筛选选择仅保留在当前歌单页面，不做偏好同步。
