# 1Panel GHCR 镜像部署

Multi User 工作流将正式版本发布到公开镜像仓库 `ghcr.io/xiao-baii/any-listen`，适用于 Linux AMD64/x86_64 服务器。部署始终使用滚动标签 `multi-user`，每次正式发布后通过 1Panel 拉取并重建即可更新，无需修改版本号。

## 准备

首次发布后，仓库维护者在 GitHub Packages 的包设置中将 `any-listen` 可见性改为 Public，再验证匿名拉取。工作流使用内置 `GITHUB_TOKEN` 发布，服务器不需要发布令牌。已有同名包须授予本仓库 Actions 访问权限。

编排默认通过南京大学 GHCR 镜像服务 `ghcr.nju.edu.cn` 拉取，直接使用镜像地址，无需将其添加到普通 Docker Hub 镜像加速配置。先在服务器验证本项目镜像可拉取，再部署。项目不提供代理变量。

将仓库中的 `compose.image.yml` 放入部署目录（例如 `/opt/any-listen`），在同目录创建 `.env`。镜像已经固定为 `ghcr.nju.edu.cn/xiao-baii/any-listen:multi-user`，不需要镜像版本环境变量。

## 首次初始化

新在线模式采用单 Node 进程和少量共享 Worker，仅支持在线音乐。管理员在扩展商店安装扩展，或通过扩展管理的“本地安装”上传 ALIX 包；在 LX API Source Loader 的扩展设置中导入并勾选脚本，再到账号页面发布配置。编辑草稿不会运行脚本。管理员播放器和普通用户使用同一已发布音源。

此编排使用 `./data:/server/data` 目录挂载，不创建命名卷。`./data` 相对于编排文件所在目录（1Panel 粘贴编排时以实际编排目录为准）。编排通过 `user: '0:0'` 以容器内 root 用户运行服务，普通 Linux 本地目录挂载无需手动建目录或修改归属；重建容器时继续使用同一目录。在线模式不需要 `./music:/music`。若移除 `user:`，则使用镜像默认的 UID/GID 1000，须确保挂载目录允许该用户写入。

全新部署在 `.env` 填写网站地址、管理员用户名和初始密码：

```dotenv
PUBLIC_ORIGIN=https://music.example.com
ADMIN_USERNAME=admin
ADMIN_PASSWORD='这里换成你自己的初始密码'
```

用户名为 3 至 32 位英文字母、数字、点、下划线或连字符，首位须为字母或数字；密码为 1 至 128 个字符。`.env` 中密码用单引号包围，避免 `$` 和 `#` 被解析；若密码包含单引号，请换一个密码或使用下述密码文件方式。

只有账号数据库为空时才自动创建管理员。缺少配置、密码不合规或密码文件无法读取时，启动失败，日志显示原因；修正配置后重新部署即可。已有账号时跳过初始化，更改环境变量不会重置密码，也不会创建另一个管理员。

环境变量可被 Docker 管理员查看，程序不会打印初始密码。首次登录直接进入播放器，可在账号页面自愿修改密码。初始化后删除 `.env` 中的 `ADMIN_PASSWORD`，重新部署容器以清除容器配置中的初始密码，账号保持不变。

仍支持密码文件：在编排中挂载仅管理员可读且容器用户 UID 1000 可读取的文件，设置 `ADMIN_PASSWORD_FILE` 为容器内路径，并移除 `ADMIN_PASSWORD`。两种密码来源不能同时提供。原 `create-admin` 命令也继续可用。

## 启动

在 1Panel「容器 → 编排 → 创建」选择服务器上的 `compose.image.yml`，确保同目录 `.env` 被加载；如果粘贴编排内容，请填写网站地址、`ADMIN_USERNAME` 和 `ADMIN_PASSWORD`，保留编排内的南京大学 GHCR 镜像地址。直接在 YAML 填密码时，用引号包围，且将密码中的每个 `$` 写成 `$$`，以避免 Compose 插值。
点击启动即可自动初始化。日志出现 `Administrator created` 和 `Any Listen account gateway listening` 表示管理员已创建、网站已启动。
编排允许拉取镜像，不限制容器内存。
在网站管理创建 HTTPS 反向代理，代理至 `http://127.0.0.1:9500`（要求 OpenResty 使用宿主机网络），支持 WebSocket、关闭缓冲，读取超时 600 秒，上传大小 16 MiB。

```bash
docker compose -f compose.image.yml pull
docker compose -f compose.image.yml up -d
curl http://127.0.0.1:9500/healthz
```

## 升级

v0.1.6 起，在线歌单的自动同步默认关闭，包括未保存该开关的已有歌单。需要自动更新时，在歌单的“编辑列表”中启用；手动“更新”不受影响。

首次从旧部署切换时，在原 1Panel 编排中修改镜像地址并移除禁止拉取的设置，保持项目名、端口和实际挂载目录不变，不创建第二套服务。旧 `.env` 的 `ANYLISTEN_TAG` 已不再使用，可删除。先核对 `./data` 解析出的宿主机绝对路径，避免重建后误用空目录。

日常升级前记录当前固定版本或镜像摘要，保留旧镜像；停止服务后备份整个 `./data`、Compose 和 `.env`。在 1Panel 执行拉取最新镜像并重建容器；仅拉取镜像或重启旧容器不会切换程序。更新期间会短暂断开，不提供自动回退。

更新后检查容器健康状态及 `/healthz`，再登录管理员账号检查运行状态、歌单和实际播放。`/healthz` 只表明入口存活。代理可能缓存旧镜像，需核对运行镜像的摘要与 Actions 发布摘要。

失败时停止新版，将编排镜像改为旧固定标签（例如 `ghcr.nju.edu.cn/xiao-baii/any-listen:multi-user-v0.1.6`，实际版本以已发布标签为准），恢复匹配的数据备份，再重建容器。恢复备份会丢失备份后的写入；修复后需将编排改回 `multi-user` 才会继续跟随正式更新。

程序没有默认密码；源码测试中的 preview 账号不包含在镜像数据中。升级和重启跳过已有账号的初始化。

运行副本、资源缓存及临时文件写入容器系统临时目录，不需要备份，具体路径见 [数据布局](multi-user.md#数据布局)。
