# Any Listen 多账号部署与维护

基于上游 `80cce020912dda64dace135c81d046cd9aad5f4d`，功能分支为 `multi-user`。
账号入口和所有账号后台运行在同一个 Node 进程，包括管理员。账号共用一个 DB Worker 和最多一个公共音源执行 Worker，各账号保留独立 SQLite 文件；管理员草稿编辑另有最多一个按需文件编辑 Worker，空闲 15 秒释放，不执行音源脚本。设计见 [改造方案](single-process-multi-user-plan.md)，代码与验证见 [开发指南](single-process-development.md)，测量见 [内存验证](single-process-memory-results.md)。

多用户模式仅支持在线音乐，管理员及普通用户均不可使用本地库、远程文件库和 WebDAV 同步；歌单备份及同账号多设备同步保留。在线路径不再创建工具 Worker，歌词繁简转换按需执行。

数据库通道按账号隔离，关闭时等待已接收的写入完成。每账号歌单缓存上限为 8 个列表及 2000 首，超额后重新查询；全站歌单缓存另有限制：最多 64 个列表及 16000 首。上述预算不包含播放队列、查询返回值或 SQLite 自身内存。单通道最多 128 个在途调用、共享 Worker 合计最多 1024 个排队任务。管理员运行状态返回 `topology`、`gatewayRss` 和共享数据库线程及通道数量；`gatewayRss` 已包含 DB Worker，不得重复累加 Worker RSS。

## 部署

要求 Docker Compose、HTTPS 反向代理和持久化卷。宿主机直接运行要求 Node.js 24、pnpm 10.34.5。
所有以下命令在仓库根目录执行。生产数据不要使用测试预览目录。

```sh
docker compose -f compose.multi-user.yml build
```

首次启动会在空账号数据库中自动创建管理员。设置 `.env`：

```dotenv
PUBLIC_ORIGIN=https://music.example.com
ANYLISTEN_TAG=multi-user-local
ADMIN_USERNAME=admin
ADMIN_PASSWORD='这里换成你自己的初始密码'
```

用户名为 3 至 32 位英文字母、数字、点、下划线或连字符，首位须为字母或数字；密码为 1 至 128 个字符。`.env` 密码用单引号包围，避免 `$` 和 `#` 被解析，含单引号的密码可改用密码文件。Compose 自动创建或复用固定名称的 `any-listen-data` 卷，程序创建卷内目录。

```sh
docker compose -f compose.multi-user.yml up -d
```

空数据库缺少有效初始化配置时启动失败，修正后重新部署。已有账号时跳过初始化，更改或移除环境变量不会覆盖密码。首次登录可直接进入播放器，无需强制改密；管理员重置密码后也可直接登录，旧会话仍会失效。初始化后删除 `.env` 中的 `ADMIN_PASSWORD` 并重建容器，账号密码保持不变。初始密码不打印到日志，但 Docker 管理员可查看容器环境变量。

1Panel 导入镜像的完整流程见 [镜像文件部署](image-import.md)。

### 可选：密码文件或手动初始化

自动初始化也支持 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD_FILE`：在 Compose 挂载密码文件，设置容器内路径，并移除 `ADMIN_PASSWORD`。密码文件须让容器用户 UID 1000 可读。不能同时提供非空的 `ADMIN_PASSWORD` 和 `ADMIN_PASSWORD_FILE`。

需要手动创建管理员时，可在服务停止且账号数据库为空的状态下初始化。将初始密码放在仅管理员可读且容器用户可读取的本地文件 `admin-password.txt`，然后执行：

```sh
docker compose -f compose.multi-user.yml run --rm --no-deps \
  -v "$PWD/admin-password.txt:/run/admin-password:ro" \
  -e ADMIN_PASSWORD_FILE=/run/admin-password \
  any-listen create-admin admin
```

密码不进入命令参数、镜像或日志；初始化后移除密码文件。用户可在账号页面手动修改密码。
网站不提供公开注册。管理员在账号页面创建用户、重置密码、禁用或恢复账号。
全站仅有一个管理员，即部署初始化（环境变量或 `create-admin` 命令）创建的账号。管理员只能创建普通用户，接口及数据库均禁止新增管理员。首次管理员已经存在时初始化命令拒绝执行。

Compose 默认仅绑定宿主机 `127.0.0.1:9500`，不设置容器内存上限，实际可用内存取决于宿主机和 Docker 运行环境。`PUBLIC_ORIGIN` 必须与浏览器地址的协议、主机和端口完全一致，不带尾部 `/`。
HTTPS 时会话 Cookie 自动设置 Secure。直连本地测试可用 `http://localhost:9500`。
反向代理必须支持 WebSocket、Range、关闭响应缓冲，并允许发布操作等待数分钟：

```nginx
location / {
    proxy_pass http://127.0.0.1:9500;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_buffering off;
    proxy_read_timeout 600s;
    client_max_body_size 16m;
}
```

入口不信任外部 `X-Forwarded-*`，限速使用 TCP 来源地址；经过反代时所有用户会共享代理 IP 的额度（15 分钟 50 次），账号额度为 10 次。反代可另加真实客户端限速。会话默认 30 天，服务端只保存令牌摘要。

## 数据布局

```text
/data/accounts.sqlite                 账号、会话、审计和发布状态
/data/users/<UUID>/app/               上游数据库、设置、deviceid、扩展
/data/users/<UUID>/cache/             私有缓存
/data/users/<UUID>/temp/              私有临时文件
/data/users/<UUID>/imports/           保留目录，在线模式不提供本地导入
/data/publications/<UUID>/            不可变音源发布版本
```

用户名修改不影响目录（当前版本不提供改名）。不支持永久删除账号。用户角色创建后固定。
个人歌单、收藏、历史、队列、设置和缓存均独立，同账号多设备按上游行为同步。
管理员可在“账号管理 → 全站设置”修改“所有资源通过服务器代理”，默认关闭，对所有账号统一生效，普通用户不可修改。配置保存在账号数据库，重启后保留；保存后同步至在线账号，新启动账号也使用该配置，当前播放不强制中断。关闭后远程资源按原始地址加载，部分资源可能受浏览器跨域或 HTTPS 混合内容限制；音源自身返回的服务器缓存地址仍按原方式访问。
自动数据库备份（启动、每日及歌单变更触发）已禁用，不清理已有备份；数据库异常时的保护性备份仍保留。
“启用在线资源”也由管理员在全站设置统一控制，默认关闭，替代各账号原来的个人开关；保存后同步至在线账号，并保留到下次启动。该选项控制原有在线资源入口，不会停止扩展或现有歌曲播放。
管理员可在全站设置编辑 GitHub 下载镜像地址，每行一个 HTTP/HTTPS 地址，保存时去重并移除末尾斜杠；源地址失败后才尝试镜像，清空仅停用自定义镜像，内置备用下载源仍保留。“恢复默认”填入上游默认列表，点击保存后生效。配置持久保存，并同步到各账号的扩展下载服务，扩展服务重启后也保留；普通用户不能修改，原有出站地址限制仍生效。
账号页面的个人备份只包含歌单，限制 16 MiB，恢复会替换全部歌单；不接受服务器路径、脚本或本地文件列表。
完整管理员数据、扩展草稿和发布版本由运维备份整个卷。普通用户不能管理扩展、执行扩展命令、导出配置和日志或操作服务器文件。
上游新增 RPC 默认拒绝普通用户，合并时须明确审查后加入允许列表。

没有账号数上限。无连接、无流和无任务默认 5 分钟后回收账号上下文；关闭浏览器标签页才会释放 WebSocket 活跃计数。
`ACCOUNT_IDLE_MS` 可修改空闲时间。后台停止期间不执行同步。账号初始化失败按请求触发退避重试，累计到 5 次后需管理员重试。公共音源 Worker 异常最多自动恢复 3 次，间隔 1、2、4 秒，随后需管理员重载或发布。
运行状态展示共享进程 RSS，各账号标记为共享进程，不能单独拆分账号 RSS。该 RSS 已包含全部 Worker，不再重复累加；容器其他开销需另行观察。
实例隔离保护账号状态；进程级崩溃会影响全站，可信管理员安装的扩展仍不是安全沙箱。

托管模式的公共 HTTP 请求库在建立连接时检查目标 IP，默认拒绝回环、内网、链路本地及保留地址；重定向也重复检查。出站代理被禁用，以免绕过地址校验。内网音源需要运维在入口进程配置 `ANYLISTEN_ALLOWED_MEDIA_ORIGINS`，值为精确 origin 的 JSON 数组，例如 `["http://192.168.1.10:8080"]`。放行意味着所有账号都能通过媒体代理访问该 origin，不能包含管理后台、数据库或云元数据地址。此限制仅覆盖公共请求库，不约束可执行任意 Node.js 代码的管理员扩展。

## 管理员音源发布

管理员进入播放器的扩展管理，安装、升级和配置：

- `online-metadata`：搜索、封面、歌词等。
- `lx-api-source-loader`：导入管理员提供的 LX 脚本，再勾选启用。仅安装加载器不等于有可用音源。

在扩展商店安装或升级受管扩展，也可通过扩展管理右上角的“本地安装”上传 ALIX 包（最多 16 MiB，仅管理员可用）。进入播放器的扩展设置，选择 LX API Source Loader，通过“导入脚本”上传 LX 脚本（最多 1 MiB），导入后勾选启用。最后返回账号页面点击“发布配置”。扩展管理页不提供“音源发布”快捷入口；发布操作只在账号页面。脚本导入使用文件草稿接口，原脚本执行命令仍不开放。
管理员修改的是文件草稿，编辑时不运行扩展或 LX 脚本；所有播放器（含管理员）均使用正式发布版本。私人登录、个人歌单或播放器能力的脚本不支持。
点击“发布配置”后，关闭草稿编辑器，快照两个扩展及脚本，停止旧公共音源，在同一执行槽验证候选，然后重建活跃账号上下文。全程只有一个音源脚本执行宿主。
配置引用、重复脚本 ID、缺失脚本、未启用脚本、加载失败都拒绝发布。LX 初始化通过当前加载器的成功日志标记验证，升级加载器后须重跑验收。
任一用户失败时回滚已切换用户，显示失败账号及回滚失败项；可重试发布。入口重启后会以账号数据库中最后成功版本修复未完成的应用操作。
首次发布失败时账号及歌单仍可使用，音源保持未发布。其他扩展和管理员私有数据不分发。
个人数据目录各自独立，发布只更新共享音源并重建内存上下文，保留个人数据。发布目录包含脚本和可能的密钥，应按敏感备份管理。
切换会重连并重新加载页面，保留服务端队列和歌单、清空旧播放地址缓存。浏览器可能要求用户再次点击播放。

## 部署兼容范围

新在线单进程模式只面向全新部署，不支持将旧本地库或 WebDAV 数据作为新模式的部署输入。源码仍保留旧迁移命令及其回归测试，供维护旧版本参考，不属于本版本推荐部署流程。

在线模式后续升级仍须备份完整账号卷，使用匹配版本的镜像和备份恢复。

## 升级与回退

停止服务并备份整个账号卷后再更换定制镜像标签。禁用网页内程序更新，统一用 Docker 升级。
回退多账号版本时恢复该版本对应的卷备份。回退旧单账号版本时使用旧镜像和迁移前原始备份，绝不直接把多账号卷交给旧镜像。
服务提供 `/healthz`，只表明入口存活；账号启动错误须在管理员运行状态中检查。

## 开发与源码交付

代码导航、测试命令、验证结果及同步 main 的注意事项统一见 [开发指南](single-process-development.md)。本机预览命令和测试账号也见该文档，不用于生产。

`main` 用于同步上游，功能改动在 `multi-user` 分支维护。推送该分支会触发 Multi User 检查；检查通过不自动生成镜像。当前发布标签为 `0.1.0`。自定义工作流在 `xiao-baii/any-listen` 的 `0.1.0`、`multi-user-v*` 标签或手动运行 `multi-user` 分支通过检查后，导出 Linux AMD64 Docker TAR 至 Actions Artifacts，保留 30 天，不推送 GHCR。镜像标签为 `any-listen:<标签或分支>` 和 `any-listen:sha-<完整提交>`。

上游 release 工作流限于原仓库执行。1Panel 文件导入使用 `compose.image.yml`，详见 [镜像导入说明](image-import.md)；本文的 `compose.multi-user.yml` 用于源码本地构建。

## 发布前外部验收

- 使用真实的两个扩展和管理员 LX 脚本验证搜索、歌词、封面、解析、持续播放和发布重连。
- 在相同账号、数据、音源及播放负载下比较改造前后的全服务内存、启动时延及发布峰值，记录 OOM、启动及音源错误。不预设人数或机器规格，不用空账号 Windows RSS 推算容量。
- 新在线模式面向全新部署，不要求旧本地库或 WebDAV 数据迁移；仍需验证在线歌单备份和后续版本升级恢复。
- 验证反向代理 HTTPS、Cookie Secure、WebSocket、Range、取消流及长时间发布请求。

这些外部条件未在本机得到验证，不能据当前自动化测试宣称已完成生产验收。
