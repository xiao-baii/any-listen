# 单进程多用户改造方案

状态：核心单进程改造已接入并通过本机自动化验证。管理员和普通账号均使用同一 Node 进程；外部持续播放及生产容器验收未完成。

本文保留设计约束与实施阶段。当前代码入口和提交检查见[开发指南](single-process-development.md)，部署以[多账号部署与维护](multi-user.md)为准。

## 实施进度

- 所有账号按实例持有配置、主题、快捷键、不喜欢列表、个人音乐缓存、歌单、播放器、资源选择、代理和连接集合。账号启动不再调用 `fork`。
- 一个共享 DB Worker 承载独立账号 SQLite 通道；歌单缓存每账号最多 8 列表/2000 首，全站最多 64 列表/16000 首。账号关闭排空写入并释放通道。
- 公共音源全站共用一个执行 Worker。管理员播放器同样使用发布版本；个人歌单和播放数据不传入音源。
- 草稿编辑复用现有扩展文件管理逻辑，通过最多一个按需文件编辑 Worker 完成；不加载扩展 VM、不执行 LX 脚本，空闲 15 秒释放。它可与正式音源同时存在，但不是第二份脚本执行实例。
- 管理员可从账号页面上传受管 ALIX 包和 LX 脚本，在现有扩展设置勾选脚本后发布。草稿配置同步写盘，避免立即发布时丢失尚未保存的设置。
- 发布关闭管理员编辑器和账号旧上下文，停止正式音源后验证候选；任一时刻只有一个音源执行宿主。失败重新加载最后成功发布版本。
- 公共音源执行 Worker 异常后最多自动重试 3 次，间隔 1、2、4 秒；之后需管理员重试。重建账号上下文清除旧地址，并使用 1012 关闭码触发客户端暂停及维护结束后重载。
- 保留在线听歌、歌单备份、同账号多设备同步；不启动本地列表扫描、WebDAV 或账号工具 Worker。
- 33 项测试通过（账号 14、数据库 4、播放器/Store 6、歌单/资源/连接 7、公共音源 1、官方扩展 1），Web 完整构建、桌面主进程构建、账号 TypeScript 检查通过。
- 本机空账号同负载对照已完成：10 个账号总 RSS 从 1499.45 MiB 降至 97.21 MiB。具体口径、限制及复现见 [内存验证](single-process-memory-results.md)，不代表真实播放节省比例。

## 已确认目标

- 目标：减少多用户场景下重复的运行环境和音源实例，控制随账号数增长的内存开销。
- 不以服务器规格和目标人数作为设计前提。不承诺未经测量的 MB 数、节省比例或容量。
- 一个 Node 进程，允许少量共享 Worker，线程数量不随账号一比一增长。
- 首版只需在线听歌，可移除新模式的本地库、WebDAV 等运行路径。
- 平衡内存收益和同步 main 的维护成本。
- 全站共享经过验证的公共音源实例；管理员统一密钥可用，需要每用户私人登录或操作个人数据的特殊脚本暂不支持，不保留每账号私有音源实例作为兼容回退。
- 全部为全新部署，无需兼容旧本地库和 WebDAV 数据。
- 发布时允许断开并重新加载，优先减少发布期间的内存占用，不保留双版本运行实例。
- 方向取舍见 [ADR 0001](adr/0001-shared-online-runtime.md)。下文为设计依据，是否完成以本文开头的阶段状态及开发指南中的验证记录为准。

## 设计结论

1. 已确认：单进程加少量共享 Worker、仅在线听歌、平衡上游兼容。
2. 已确认：全新部署，无旧数据兼容；发布允许断开重载，采用串行切换。
3. 已确认：公共音源全站共享，个人状态脚本暂不支持，个人音乐数据仍隔离。
4. 缓存和队列的具体容量属于可逆的实现参数，使用有界默认值并通过实测调整，不要求用户指定内部数值。
5. 需求层面的分支已明确，按下列阶段推进；完成状态以文档开头的实施进度为准。

## 推荐架构

一个 HTTP/WebSocket 入口负责认证和路由。账号上下文持有账号自己的配置、播放器状态、会话连接集合、任务取消句柄和服务引用。主线程不执行耗时脚本和大型同步数据库操作。

初版从一个共享 DB Worker 和一个共享音源 Worker 开始；工具 Worker 仅在在线功能确有需要时按需创建。音源 Worker 内每个启用的受管扩展和脚本各有一个全站实例，“全站一份”不表示只能配置一个音源。新增账号仅增加轻量账号状态及按需数据库资源，不创建专属进程、DB Worker 或音源 Worker。

| 对象 | 归属 | 生命周期 |
| --- | --- | --- |
| 静态资源、默认配置、全站设置 | 全站 | 进程期间 |
| 歌单、队列、历史、个人设置 | 账号 | 持久保存，内存状态可按需加载和回收 |
| WebSocket 连接 | 登录会话，关联账号 | 连接期间，撤销登录时立即关闭 |
| 音乐数据库连接、预编译语句和歌单缓存 | 账号 | 按需打开，无任务且完成写入后可关闭 |
| 经过验证的公共音源实例 | 发布版本及实际配置范围 | 版本生效及在途请求期间 |
| 带个人状态的音源脚本 | 不支持 | 不创建每账号兼容实例 |
| 管理员编辑和验证 | 草稿或候选版本 | 编辑保存文件，执行验证复用发布维护期的音源 Worker |
| 工具执行线程 | 全站共享 | 在线能力确有需要时按需创建，任务显式携带输入和账号资源权限 |

同进程不能保证与现有每账号进程相同的崩溃隔离。Worker 只能提供部分执行隔离，进程级故障仍可能影响全站，这是选定单进程模式的限制。音源 Worker 故障时失败结束其在途请求，按有限次数退避恢复；账号和歌单服务继续工作，不能将其宣传为完整的进程故障隔离。

### 在线功能范围

新多用户模式移除本地目录扫描、文件监听、本地音乐元数据解析、WebDAV 列表和 WebDAV 同步的入口及启动任务。不能只隐藏 UI 而继续加载和启动这些服务。

建议保留在线搜索、歌单、收藏、历史、队列、播放、歌词/封面、同账号多设备同步、管理员发布和歌单备份。WebDAV 同步与同账号多设备同步不是同一功能，删除前者不推导为删除后者。

工具能力只保留在线路径真正需要的部分，例如歌词繁简转换。先复用已有纯函数，重依赖按需加载；如确有计算压力才交给共享工具 Worker，不为已删除的功能保留常驻线程。

桌面和原单用户模式继续保留原有本地/WebDAV 实现，新模式通过独立组合入口和按需导入排除这些模块，避免为缩减 Web 功能删除上游公共实现。

### 账号状态

请求进入时从服务端认证结果取得账号身份，创建或获取对应上下文。不能信任客户端直接传入的 userId 作为授权依据。

服务实例、事件订阅、定时任务和跨 Worker 消息显式绑定所属账号。移除通过切换全局变量、全局目录或“当前用户”选择账号的路径。异步上下文只能辅助传递身份，不能替代状态隔离。

共享代码只共享不可变内容和无状态逻辑。播放器、歌单变更事件只向同账号连接广播；每次操作仍执行管理员权限和会话撤销检查。

对所有事件总线、广播、查找连接和踢出连接检查账号归属，特别是 `src/modules/ipc/websocket.ts` 当前遍历所有连接的广播。销毁账号实例时成对清理监听器、定时器和取消句柄；绑定实例的方法在后台任务中也不能重新查找全局“当前账号”。保留现有断开后的空闲回收行为，首版不增加开着页面的账号自动休眠协议。

### 数据库

建议继续复用现有每账号 SQLite 文件和表结构，以减少业务 SQL 改造和同步 main 的成本。这是实现复用选择，不是旧数据兼容要求；不建设旧账号数据导入、本地曲目过滤或 WebDAV 数据迁移流程。新部署产生的在线歌单等数据仍需持久化、备份，并支持之后的版本升级。

先将数据库连接、语句和缓存改为账号所属的服务实例，再接入有界的共享 DB Worker。每个账号在同一时刻绑定一个 Worker，保持原有操作顺序和事务边界；Worker 数量根据测量配置，不随账号逐一创建。

不同账号的队列需要公平调度、长度限制和取消机制；长时间同步查询仍会阻塞所在 Worker，不能宣称共享池消除了相互影响。已有多 Worker 调度基础不充分时，先从一个共享 DB Worker 验证正确性，再按实际阻塞情况扩展。

限制每账号缓存和全局缓存总量。缓存缺失必须从数据库恢复，包括目前依赖缓存命中的按 ID 查询。回收先停止接受任务，等待在途写入及延迟保存完成，再关闭连接和清理引用。

### 音源和扩展

先适配当前受管的 `online-metadata`、`lx-api-source-loader`，用真实扩展和实际脚本验证；不能仅凭扩展 ID 或相同配置判定可以共享。

音源共享的是公共搜索、歌词、封面和播放地址解析能力，管理员统一配置的密钥可以使用。账号密码、登录会话和个人音乐数据不交给公共音源。公共结果缓存键包含发布版本、音源、请求参数及影响结果的配置；个人编辑歌词等仍按账号存储，不能混入公共缓存。

公共宿主不暴露个人歌单、个人播放器或私人凭据的读写能力，后台回调也执行相同限制。依赖这些能力的脚本在验证阶段拒绝发布并给出具体原因；不能退回到全局“当前账号”或每账号私有实例。仅通过初始化不能证明任意脚本并发安全，须对支持的扩展版本与实际音源脚本进行并发验证，运行期继续限制能力并处理超时和异常。

媒体代理地址继续与账号授权关联。共享解析得到的结果不能直接把某账号的私有代理地址返回给其他账号。相同公共请求合并时，一个用户取消不能中止其他等待者。

初版不要求合并跨用户在途请求，以减少取消语义复杂度。音源调用设置有界队列、超时和并发上限，对尚未证明可并发的脚本串行调用，验证后再提高并发度；多账号共享一个实例不等于允许无限并行。媒体继续采用流式转发和背压，不将完整音频常驻内存。

### 发布和回滚

草稿、候选版本、正式版本的持久文件分离。首版建议将需要运行脚本的草稿验证统一放入发布维护期，安装、导入和编辑配置只修改草稿文件，不单独保留运行中的草稿宿主，也不因普通编辑中断公共播放。发布时先停止正式实例，再加载候选实例验证，避免同时保留完整执行实例。

发布流程：进入维护状态，暂缓新的音源请求；停止相关播放及在途解析，保存账号队列和进度，断开需要重新加载的客户端；等待旧实例销毁及受其持有的资源释放，再在同一个执行槽加载并验证候选版本。验证成功后持久提交生效版本，清理旧播放地址和代理映射，解除维护并让客户端重新加载。直连外部资源的浏览器播放需要客户端配合暂停，不能靠关闭服务端连接保证停止。

验证或提交失败时先销毁候选实例，再重新加载上一个成功发布版本；此时服务短暂不可用，不能描述成无缝回滚。若旧版本也启动失败则显示音源不可用并允许管理员重试，账号及歌单服务继续工作。发布中断后以最后持久提交的成功版本恢复，未提交候选不得自动生效。

前端需要识别发布维护状态，暂停自动重连和音源重试，完成后统一恢复，避免重载风暴。音源执行槽复用或销毁重建 Worker，线程数量保持有界；当前一次性验证子进程迁移到该执行槽。没有旧版本排空宽限期或双版本常驻机制。

| 0 | 记录主线程、Worker、音源初始化及典型操作的内存与时延基线 | 同一数据和脚本可重复对比；测量不作为人数和机器规格的前置要求 |

| 2 | DB 连接及缓存实例化，共享 DB/工具 Worker | 一个 Worker 承载多个账号时读写不串号；无每账号常驻工具 Worker |

| 4 | 将普通账号 HTTP/RPC 及状态放入共享入口，移除其 fork | 多账号在同一进程使用，连接和任务可正确回收；共享状态清单逐项核对 |
| 5 | 管理员草稿编辑与运行拆分，发布验证迁移至音源执行槽，客户端支持维护后重载 | 最终只运行一个 Node 进程；无双版本音源实例；失败按最后成功版本恢复 |
| 6 | 内存、延迟、持续播放及上游兼容验收 | 报告真实收益和退化；没有证据不宣称容量或收益达标 |

上述阶段用于拆分验证，不表示阶段 1 已降低内存，也不把普通账号合并后仍有管理员子进程的中间状态称为最终单进程。

## 内存收益来源

- 删除每账号完整 Node 后台和每账号三类 Worker 的重复初始化开销。
- 受管扩展、预加载代码和音源脚本按全站加载，不再按账号数复制。
- 新在线入口不初始化本地扫描、文件监听和 WebDAV 依赖。
- 歌单、数据库连接和代理映射采用有界缓存及显式释放，防止常驻状态持续累积。
- 发布采用串行版本替换，降低新旧音源同时存在的峰值。

个人状态和并发请求仍随使用量增长。验收比较同样账号和脚本下的总内存、每新增活跃账号的内存增量及发布峰值，同时报告延迟和 CPU 变化；不设用户未要求的机器容量目标，不预报节省比例。

## 同步 main 和部署恢复

托管入口和适配器优先放在 `packages/web-server/src/accounts/`。共享模块在确实存在状态归属问题的位置增加实例化入口，保留桌面和单用户模式的默认调用行为，避免复制整套业务代码。

按可独立构建和验证的完整改动提交；本次服务实例、账号入口和测试相互依赖，不按历史实施阶段强拆提交。后续修复单独提交，避免格式化和无关重命名。合并 main 时审查新模块状态、Worker API、扩展 API、RPC 权限表和数据库迁移；仅通过 Git 合并不足以证明行为兼容。

新模式使用全新数据目录，不增加旧数据迁移工具、旧目录自动识别或新旧模式共享数据的兼容开关。开发时分阶段复用旧运行拓扑仅用于验证，不承诺将新模式产生的数据交给旧多进程版本使用。

正式上线后的升级仍需备份数据。恢复时使用匹配版本的程序和备份，禁止两种模式同时写同一账号数据。全新部署不授权清理现有仓库或部署目录中的数据。

## 验收重点

- 账号 A/B 使用相同歌单 ID、配置文件名和歌曲 ID，交错读写不会混用。
- A 退出或禁用后立即失去资源访问；B 的播放和请求不被取消。
- 同账号多设备保持同步；不同账号不会收到对方的播放或歌单事件。
- 数据库缓存淘汰、上下文回收后重建、进程正常退出后恢复，数据一致。
- 扩展超时、异常、取消和共享 Worker 重启均有明确结果；在途请求有界，不泄漏监听器。
- 新增账号不增加专属线程；同一启用脚本仅存在一份全站运行实例；依赖个人能力的脚本不得绕过发布或运行期限制。
- 发布会取消旧请求和代理流，前端暂停播放与自动重连；任一时刻不保留双版本音源执行实例。
- 发布失败、版本提交失败、发布期间重启可按最后成功版本恢复；旧版本恢复失败有明确状态，不形成无限自动重试。
- 全新部署可初始化账号和在线歌单；不启动本地/WebDAV 服务；之后的正常升级、重启和备份恢复保持在线数据完整。
- 同样负载下对比全服务内存、每新增活跃账号的增量、GC/CPU、事件循环延迟、解析与查询时延；观察长期增长。
- 账号进程 RSS 已含该进程的全部 Worker，不能把各 Worker RSS 再相加。堆指标按线程分别采集，容器总内存另行观察。
- Web、桌面、既有账号和扩展测试均执行，桌面基线已有问题单独记录。

指标语义参考 [Node.js process.memoryUsage](https://nodejs.org/api/process.html#processmemoryusage)；Worker 资源限制不能提供完整进程内存上限，参考 [Worker resourceLimits](https://nodejs.org/api/worker_threads.html#new-workerfilename-options)。
