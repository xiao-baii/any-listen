# 在线多用户采用共享进程和少量 Worker

为减少每账号重复运行完整后台的内存开销，新多用户模式采用单个 Node 进程及少量共享 Worker，范围限定为在线听歌，移除本地库和 WebDAV 等功能的运行路径。用户选择平衡内存与同步 main 的成本，因此改造优先复用现有存储结构和业务逻辑并兼容桌面和原单用户入口；代价是必须显式隔离账号状态，并接受进程级故障可能影响全部用户。

用户确认仅面向全新部署，不建设旧本地库和 WebDAV 数据的迁移兼容；存储结构复用出于维护成本，而非旧数据承诺。用户同时选择发布时允许断开重载，优先减少内存，因此正式和候选音源串行加载，不维持双版本实例；失败时重新启动上一成功版本，接受期间音源短暂不可用。

音源采用全站共享实例，管理员统一配置的密钥可以作为公共配置。需要每用户私人登录、读取或操作个人歌单及播放器的特殊脚本暂不支持，不以每账号实例作为回退；代价是缩小脚本兼容范围，换取不随账号数重复初始化音源的内存收益。用户歌单、收藏、队列、历史和播放状态继续独立。

实施时复用上游扩展包验证和文件管理，将草稿编辑放入最多一个按需文件编辑 Worker，空闲 15 秒释放。该 Worker 禁止创建脚本 VM，没有预加载执行代码；它可与正式音源并存，但不构成第二份音源执行实例。发布前关闭编辑器，正式和候选仍严格串行执行。此取舍保留上游签名校验及配置逻辑，避免复制一套扩展安装系统。
