# 单进程内存验证（2026-09-15）

本机 Windows x64、Node.js 26.2.0；旧版为 `fa74bd80`，新版为本次单进程改造源码（2026-09-15 测量时尚未提交，不对应已发布标签）。
两版分别使用全新临时目录，创建相同数量的空账号（含一个管理员），没有发布音源脚本，没有媒体播放，也没有导入歌单。
因此这是重复后台初始化开销的对照，不是实际播放容量或生产环境验收。

旧版总量为测量入口 RSS 加各账号进程最近上报的 RSS；新版为测量进程 RSS。Worker 的 RSS 不重复累加。
每个档位等待 2 秒，主线程调用 GC 后间隔 250 毫秒采样 5 次，报告中位数；旧账号子进程不强制 GC，使用实际运行上报值。
本表为一次完整运行的观测，未报告多次运行置信区间；后台服务已启动但未打开浏览器，因此不含浏览器内存。

| --- | ---: | ---: | ---: | ---: |
| 1 | 195.67 | 89.84 | 54.1% | 2 / 1 |
| 3 | 486.89 | 91.19 | 81.3% | 4 / 1 |
| 5 | 774.70 | 91.69 | 88.2% | 6 / 1 |
| 10 | 1499.45 | 97.21 | 93.5% | 11 / 1 |

从 1 个增加至 10 个空账号，旧版平均每账号增加约 144.9 MiB，新版约 0.82 MiB。该增量不适用于已加载大量队列、正在播放或使用真实脚本的账号。
旧版账号启动约 843–916 毫秒；新版首账号 149 毫秒，之后 43–50 毫秒。测量主线程事件循环 p99 约 17–23 毫秒，不是数据库或资源请求延迟。

新版本始终一个共享 DB Worker；没有发布音源时不创建公共音源 Worker。管理员查看或修改草稿时最多一个文件编辑 Worker，空闲 15 秒释放，禁止执行扩展和脚本。
发布之后最多一个公共音源执行 Worker。官方扩展测试验证管理员与普通用户共用进程、发布替换、账号独立代理 URL 和执行 Worker 崩溃恢复。

关闭全部账号后，新版主线程堆从 21.84 MiB 降至 20.75 MiB，RSS 为 94.94 MiB；共享代码和 DB Worker 仍驻留，V8 和分配器不保证立即把空闲内存还给操作系统，不能把 RSS 未回到冷启动值直接解释为泄漏。

## 复现

两版使用相同 Node 版本和 pnpm 10.34.5，分别构建 Web；不要在运行预览时覆盖它所用的构建目录。

```sh
node packages/web-server/tests/memory.cjs

# BASELINE 是旧提交的独立、已构建工作目录；不可指向生产数据。
ACCOUNT_BASELINE_ROOT=/absolute/path/to/BASELINE node packages/web-server/tests/memory.cjs
```

PowerShell 使用 `$env:ACCOUNT_BASELINE_ROOT='F:/any-listen/work/memory-baseline'` 设置旧版目录；新版测量前用 `Remove-Item Env:ACCOUNT_BASELINE_ROOT` 清除。
本次本机保留旧版独立工作目录 `work/memory-baseline`，该目录由 Git 忽略，不随仓库上传。其他机器可用 `git worktree add --detach work/memory-baseline fa74bd80` 创建独立基线，再在其中安装依赖并构建 Web。测量脚本只清理它创建的临时账号目录。

## 未验证

真实管理员 LX 脚本、公网歌曲持续播放、Linux Node.js 24 容器、生产 HTTPS 代理、发布峰值与长期内存趋势尚未完成。
不能把表中的 93.5% 当作真实播放节省比例。部署前使用相同脚本、歌单和播放负载比较总内存、发布峰值、CPU、查询与音源请求延迟。
